# A notification badge is a system

**Caption:** Notification badge is a system.
**Hook:** The little alert dot looks trivial, but it is a set of rules about size, position, meaning and lifecycle.

## Main rule
Treat badges as a system with six rules: cap the number (99+), anchor the badge to the icon's corner so it grows outward without moving the icon, use a number for "how many need action" and a dot for "something changed / a state" (never both on one item), clear the badge as soon as the user opens the view, animate counts upward without flashing to 0, and badge only items that need a decision.

## Before / after
- **Uncapped vs capped (0:02-0:08).** Bad: the pill grows with every digit (1 → 494 → 1225), and in the nav example the Inbox badge pushes "Archive" and "Settings" sideways ("reflows"). Good: cap at "99+"; width is bounded, a lock icon marks it, the nav layout holds ("locked"). Why: a bounded badge never reflows its neighbours, and beyond 99 the exact number carries no extra decision value.
- **Reflowing vs anchored (0:09-0:13).** Bad: the badge sits in the flow, so as the number widens the bell icon slides left (0 → 24 → 38 → 48 px). Good: the badge is pinned to the top corner of the icon and grows leftward/outward over it; "icon fixed, grows left". Why: the icon is the tap target and the recognisable landmark; if it moves, users mis-tap and lose their spatial memory.
- **Count vs status (0:14-0:20).** A numbered badge on a bell ("count · action, a number you clear") vs a presence dot on an avatar ("status · state, a condition, no number"). Comparison table: answers "how many" vs "which state"; you must "act now" vs "nothing"; changes on "each new item" vs "presence". Why: they are different signals with different rules; mixing them makes users unsure whether a mark demands action.
- **One signal per row (0:21-0:25).** Good rows: Miles Reyes with only a dot ("changed"), Priya Nair with only a count 5 ("how many"). Bad row: Deploy Bot with a dot and a "3" ("which one?", flagged "noise"). Rule: "Dot or number, never both on the same row". Why: both answer the same question twice, which doubles visual weight without adding information.
- **Lingering vs clearing (0:26-0:32).** Good: opening the inbox marks rows read (check marks) and the header badge disappears, label "cleared". Bad: rows are read but the badge still says 12 ("still 12?"). Why: a badge that survives being looked at trains users to ignore all badges (badge blindness).
- **Blink vs roll up (0:33-0:39).** Good: the count rolls up 3 → 4 → 5 → 6 → 7. Bad: between increments the badge flashes to 0 (5 → 0 → 6 → 0 → 7). Why: a momentary reset reads as a bug and as "everything cleared", breaking trust in the number.
- **Badge everything vs badge decisions (0:40-0:45).** Bad: Messages 4, Mentions 9, Product updates 2, Promotions 17, System 1 (5 badges). Good: only Mentions 3 is badged (1 badge). Why: when every category is badged nothing stands out and the alert colour stops meaning "act"; a signal needs silence around it.

## Do
- Cap displayed counts at 99+ (or 9+ for very small badges).
- Position the badge absolutely at the icon's top-end corner; let it expand toward the inside/start so the icon never shifts.
- Use a count badge for actionable items the user clears; use a dot for state (online, changed) without a number.
- Clear the badge the moment the relevant view is opened (or items are marked read).
- Animate increments as a roll-up from the previous value; update in place.
- Restrict badges to categories that need a user decision (e.g. mentions, review requests).
- Reserve the alert colour for counts that need action and the success/online colour for presence.

## Don't
- Don't let badge width push siblings in a nav or toolbar.
- Don't place the badge inline in the layout flow next to the icon.
- Don't show a dot and a number on the same item.
- Don't keep a badge after the user has seen the content.
- Don't reset the displayed count to 0 between updates (e.g. re-render with an empty initial state).
- Don't badge promotions, product updates or system noise.

## Voice-over summary
- The alert dot is a system, not decoration.
- Cap the count: 200 shows 99+, keeping the shape stable; pin the badge to the top corner so the icon never moves whether there is one digit or three.
- Alert colour means act now, success colour means online: a counting badge and a status dot are different objects; a dot says something changed, a number says how much, showing both is noise.
- The badge clears the moment the view opens; one that lingers trains people to ignore every badge.
- When the count rises it ticks up and never flashes to zero, which reads as a bug.
- Badge only what needs a decision; badge everything and the colour stops meaning anything.

## Notes for the skill
- CSS: icon wrapper `position: relative`; badge `position: absolute; top: 0; inset-inline-end: 0; transform: translate(50%, -50%)` (mirror for RTL), `min-width` equal to its height with horizontal padding so 1 digit is a circle and 2-3 characters become a pill; `font-variant-numeric: tabular-nums` to keep width stable while counting.
- Count roll-up: animate from the previous value (keep the old value in state, never mount with 0); keep it short (well under 300 ms) and skip the roll animation under `prefers-reduced-motion: reduce`.
- Accessibility: the badge number is not announced unless it is part of the accessible name. Put it in the control's label, e.g. `aria-label="Notifications, 12 unread"` (or "more than 99 unread" when capped), and hide the visual badge with `aria-hidden="true"`. Announce changes via a polite live region sparingly. Do not rely on colour to distinguish status from count; the dot vs number shape difference plus text labels carry the meaning (WCAG 1.4.1).
- Status dots on avatars need a text equivalent ("online") and at least 3:1 contrast against both the avatar and the background (a separating ring helps).
- The voice says "one unread shows a single dot", but the screen shows a "1" badge; for actionable items keep the number, use a bare dot only for state or "new" without quantity.
- Width labels (96 / 181 / 227 / 184 px) belong to the zoomed demo, not to real badge dimensions; typical real badges are 16-20 px tall.
- Clear-on-open has an edge case: in long lists, clear per item as it is viewed (or on explicit "mark all read"), not the whole count when only the first screen was seen.
