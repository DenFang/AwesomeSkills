# Nested corners: inner radius = outer radius minus padding

**Caption:** Using the same radius inside and outside a card is a fast way to make it look machine-made; nested corners should share one centre: subtract padding, subtract borders, give edge-to-edge images the card radius only on touching corners, and apply the same rule to controls inside controls.
**Hook:** A zoomed card corner shows the gap between the outer and inner curve is 8 px on the straight sides but 11.3 px at the corner.

## Main rule
Nested rounded shapes must be concentric: inner radius = outer radius - padding (and - border width). With equal radii the gap swells at the corner because the two arcs have different centres.

The 11.3 figure is exact geometry: with equal radii the corner gap is padding x sqrt(2), and 8 x 1.414 = 11.3, independent of the radius.

## Before / after
- **Equal radii vs concentric radii (video slide).** Bad: outer and inner curves with the same radius; their centres C1 and C2 sit 8 px apart on each axis, so the band between them is 8 px on the sides and 11.3 px across the corner, which reads as a lumpy, uneven border. Good: inner radius reduced so both arcs share centre C1; the band is 8 px everywhere. Why: the eye judges a nested frame by the evenness of the band; a fattened corner breaks the parallel-lines gestalt and looks careless.
- **Ignoring the border (caption only).** Bad: subtracting only the padding when the outer box has a border. Good: inner radius = outer radius - border width - padding. Why: the border also offsets the inner edge from the outer curve.
- **Image flush to the card edge (caption only).** Bad: rounding all four image corners, or none. Good: the image takes the card radius only on the corners that touch the card edge (e.g. top-left and top-right for a top image), square elsewhere.

## Do
- Compute inner radii from tokens: `border-radius: calc(var(--radius-outer) - var(--pad) - var(--border))`.
- Clamp at zero: when padding is larger than the outer radius, the inner element is square (`max(0px, ...)`).
- For flush media, either clip with the parent (`overflow: clip` on the card) or set radius only on the touching corners.
- Apply the same subtraction to controls nested in controls: a button inside an input, a segment inside a segmented control, a chip inside a pill.

## Don't
- Don't reuse the outer radius token on inner elements.
- Don't forget borders, outlines that take layout space, or nested padding levels (each level subtracts again).
- Don't round the image's inner corners that sit against card content.

## Notes for the skill
- Formula: `r_inner = max(0, r_outer - padding - border)`. For several nesting levels apply it per level.
- When the inner element's radius would become tiny (1-3 px), consider making it square or increasing the outer radius instead; very small radii look like rendering errors.
- Optical note: some designers add 1 px back to the inner radius at small sizes for optical balance; that is a taste adjustment, the concentric rule is the baseline.
- CSS: `overflow: clip` (or `hidden`) on a rounded parent clips flush children to the parent's curve, which is the simplest way to satisfy rule 3; beware it also clips focus rings and popovers of descendants, so do not clip containers that hold focusable controls whose outline extends outside.
- Focus rings drawn with `outline` are meant to follow `border-radius` (check current support); with `outline-offset` the ring is a further concentric offset, so by the same rule its radius should be the element radius plus the offset, not equal to it. If you draw the ring yourself (box-shadow or pseudo-element), compute that radius explicitly.
- No accessibility conflict; purely visual.
