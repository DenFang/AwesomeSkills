# KPI rows: flag what is off, name the period, show the goal

**Caption:** A KPI row should surface the number that needs attention before the reader scans the rest; three rules: colour only the off number, give every delta its comparison period, show the target and not just the value.
**Hook:** A KPI row exists to point at the one number that needs you.

## Main rule
In a KPI row keep every value neutral except the one that is off target; label every change with its comparison period; and show each value against its goal (e.g. a progress bar to target), so status is clear before the digits are read.

## Before / after
- **Value alone vs value with goal (video slide).** Bad (implied): a big number and a delta with no reference point, so the reader must know the target to judge it. Good: a bar from 0 to the target with the value and target as a fraction, the deadline, and a plain-language status line. Why: a filled bar is read pre-attentively by length, so on-track or late registers before reading any digit.
- **Everything coloured vs only the off number (caption only).** Bad: every delta tinted in success or danger colours. Good: neutral values, and a single highlighted one where action is needed. Why: if everything is coloured, colour stops carrying signal (the von Restorff effect works only for the exception).
- **Bare delta vs delta with period (caption only).** Bad: +8%. Good: +8% vs last quarter (or vs Q3, vs last 7 days). Why: a change without a baseline cannot be interpreted.

## Do
- Keep KPI values and deltas in neutral text; reserve the warning or danger role colour for values that breach a threshold.
- Write the comparison period next to every delta (vs Q3, vs last week, MoM).
- Show goal context: value / target, a progress bar or bullet chart, the deadline, and a short status sentence.
- Pair colour with a non-colour cue (icon, word like Behind or At risk, arrow direction).

## Don't
- Don't colour every positive delta in the success colour and every negative one in the danger colour by default; a negative delta can be good (costs, churn).
- Don't show percentages without the base period.
- Don't make readers remember the target from elsewhere.

## Notes for the skill
- Inconsistency in the post itself: the sample delta on slide 4 is +8% with no period, which breaks the carousel's own rule 2. Write it as +8% vs Q3 (or similar).
- Unclear on screen: the bar uses a warning-role colour at rest although the status says on track; if colour means status, an on-track bar should be neutral or success-coloured, and the warning colour reserved for off-track goals (that is rule 1 applied to bars).
- WCAG 1.4.1 (use of colour): colouring only the off number must be backed by text or an icon (Behind target, a down arrow with an accessible name). WCAG 1.4.11: the bar fill needs 3:1 contrast against its track if it conveys the value.
- Semantics: a goal bar is a `<meter>` (or `role="meter"`) with min, max and value, or `role="progressbar"` with `aria-valuenow`/`aria-valuemax`; give it an accessible name like Q4 goal and `aria-valuetext` such as 48.2k of 60k, 80 percent. Keep the visible fraction text as well.
- Count-up animations: decorative only; disable under `prefers-reduced-motion: reduce` and make sure screen readers get the final value, not intermediate numbers (do not put the animating number in a live region).
- On-track status should be computed against elapsed time (progress vs share of period elapsed), not against an arbitrary threshold; say which logic the status uses.
