# AI prompt input: five designed states

**Caption:** Why does an AI input feel premium? Five states, one component (plus a plug for the author's plugin).
**Hook:** An AI chat input feels premium; taking it apart shows why.

## Main rule
Design every state of a chat composer explicitly: a quiet idle state, a focus ring that does not
change the border width, a send button that becomes active only when there is content, a text area
that grows upward while the toolbar stays fixed, attachments that upload inline with progress (no
modal), and a send button that turns into Stop while the answer streams.

## Before / after
The reel is a state walkthrough rather than a bad/good comparison. Each state with the mechanism:
- **Idle (0:05-0:07).** Placeholder "Ask anything", muted toolbar (+, model picker, Search, mic) and
  a disabled-looking send button; suggestion chips above. Why: a quiet resting state keeps attention
  on the page content and offers starting points without demanding action.
- **Focus (0:07-0:10), step 01 "Focus ring, not a border swap".** A soft outer ring/glow appears
  around the container; the border does not change thickness. Why: changing border width shifts
  layout by 1-2 px ("the border doesn't jump"); a ring drawn outside (box-shadow / outline) signals
  focus with zero layout shift.
- **Has content (0:11-0:14), step 02 "Send wakes up with content".** The send button switches from
  muted to filled accent as soon as there is a character. Why: the button's state mirrors whether the
  action is possible, so the user knows Enter/Send will do something.
- **Growing text (0:14-0:19), step 03 "Grows with the text, toolbar stays put".** The field expands
  upward as lines are added; the toolbar row and send button keep their position at the bottom. Why:
  the controls the user is about to press do not move under the cursor/thumb, and the composer
  stays anchored to the bottom of the chat.
- **Attachment (0:19-0:23), step 04 "Uploads in place, no modal".** A dropped PDF appears as a chip
  above the text with a circular progress ring ("Uploading 83%"), then shows its size (2.4 MB); an
  image thumbnail sits next to it. Why: the user keeps the context of the message they are writing
  instead of being taken into an upload dialog.
- **Generating (0:23-0:27), step 05 "Send becomes Stop".** After sending, the same button shows a
  stop square with a spinning ring while the answer streams. Why: the most likely next action
  (interrupt) appears exactly where the user's pointer already is, and the ring shows ongoing work.

## Do
- Draw focus with `outline`/`box-shadow` outside the border, keeping border width constant.
- Disable or mute Send until the trimmed input (or an attachment) is non-empty; enable on the first character.
- Auto-grow the textarea upward up to a max height, then scroll inside it; keep the toolbar fixed.
- Show attachments as inline chips with per-file progress, size, and a remove control.
- Swap Send for Stop in the same slot during generation, and restore Send when done or stopped.
- Offer a few suggestion chips in the empty state.

## Don't
- Don't swap a 1 px border for a 2 px border on focus (layout shift).
- Don't open a modal for file upload from a composer.
- Don't let the toolbar or send button move as the text grows.
- Don't leave Send looking active on an empty input.

## Notes for the skill
- Focus visibility: the "soft" ring must still meet WCAG 2.4.7 and, ideally, 2.4.13 (focus indicator
  at least 2 px thick with 3:1 contrast against adjacent colours). A faint glow alone on a dark
  background often fails; use `:focus-visible` (or `:focus-within` on the container) with a solid
  ring plus optional glow.
- Disabled Send: prefer `aria-disabled="true"` over the `disabled` attribute if you want the button
  focusable with an explanatory tooltip; Enter on an empty field should do nothing. Shift+Enter
  inserts a newline; Enter sends (document this behaviour).
- Auto-grow: `field-sizing: content` (where supported) or JS height = scrollHeight, with a
  `max-height` (e.g. about 40-50% of the viewport) and internal scroll. Growing "upward" happens
  naturally when the composer is bottom-anchored (flex column, `justify-content: flex-end`).
- Upload chips: expose progress via `role="progressbar"` with `aria-valuenow`, give the remove button
  an accessible name ("Remove Q3-report.pdf"), handle failure with a retry state, and block or queue
  Send while uploads are incomplete.
- Stop button: change the accessible name with the icon ("Send message" -> "Stop generating"),
  announce generation start/end in a polite live region, and keep the hit target at least 44x44 px
  (the reel's round button is about that size). The spinning ring should stop under
  `prefers-reduced-motion: reduce` (keep a static indicator).
- Drag-and-drop: also support paste and the + button file picker, and show a drop-zone highlight on
  dragover so the "uploads in place" behaviour is discoverable.
