# Five navigation patterns, one system

**Caption:** Navigation system is the key to good UX.
**Hook:** There are five common navigation patterns; picking the wrong one loses users.

## Main rule
Choose navigation by platform and hierarchy depth: bottom tabs for 3-5 top destinations on mobile, a persistent sidebar on desktop for 5+ sections or hierarchical content, the hamburger only for secondary items, a command palette only as an accelerator next to visible navigation, and breadcrumbs only when the hierarchy is deeper than two levels.

## Before / after
The video presents each pattern as a Rule / Avoid pair rather than side-by-side mockups:
- **Bottom tabs.** Rule: "3-5 destinations · mobile only · always visible". Avoid: hiding the same destinations in a hamburger, "drops engagement 40%". Why: always-visible labelled tabs show the app's scope at a glance and stay in thumb reach; hidden items are out of sight, so they are used less.
- **Persistent sidebar.** Rule: "Persistent · desktop · 5+ sections". Avoid: "Collapsed by default kills discoverability". Why: on wide screens there is room to keep the full hierarchy in view, which serves orientation and recall; collapsing it trades a little space for lost discoverability.
- **Hidden menu (hamburger).** Rule: "Mobile only · secondary navigation" (demo drawer: Profile, Settings, Billing, Notifications, Help center, Sign out). Avoid: "Desktop hamburger drops engagement 56%". Why: secondary, infrequent items can live behind one tap; primary destinations hidden behind an icon lose their information scent.
- **Command palette.** Rule: "Power users · Cmd K · search-driven" (demo: "Type a command" with items Search project files / Go to, Open settings / Action, Switch theme / Action, Recent files / View). Avoid: "New users don't know it exists". Why: a palette is invisible until summoned, so it accelerates experts but cannot teach the structure to newcomers.
- **Breadcrumbs.** Rule: "Hierarchy depth > 2 levels". Avoid: "Flat structure breadcrumbs add noise". Why: breadcrumbs communicate position in a deep tree; in a flat structure they repeat what the page title already says.

## Do
- Mobile: bottom tab bar with 3-5 labelled top destinations, always visible.
- Desktop: persistent sidebar when there are 5+ sections or hierarchical content; allow collapsing, but default to expanded.
- Put only secondary items (settings, account, billing, support, sign-out) in a hamburger / drawer.
- Offer Cmd K / Ctrl K as an accelerator in addition to visible navigation, and advertise the shortcut (e.g. in the search field or menu items).
- Add breadcrumbs only when the hierarchy is deeper than two levels.

## Don't
- Don't hide primary navigation behind a hamburger, especially on desktop.
- Don't put more than five items in a bottom tab bar.
- Don't collapse the desktop sidebar by default.
- Don't make the command palette the only path to a feature.
- Don't add breadcrumbs to a flat site.

## Voice-over summary
- Five navigation patterns; picking the wrong one loses users.
- Tab bar for mobile: three to five top-level destinations, always visible and thumb-reachable; beyond five, users cannot parse the options.
- Sidebar for desktop when content is hierarchical or there are more than five sections: persistent, collapsible, never hidden behind a click.
- Hamburger only for secondary mobile content (settings, account, support), never primary; claims studies show 40% fewer users click hidden menus.
- Command palette (Cmd K) is search-driven navigation for power users (cites Linear, Notion, Raycast), never primary for new users; breadcrumbs only beyond two levels, they show position, not navigation. Summary: "Mobile equals tabs. Desktop equals sidebar."

## Notes for the skill
- Platform guidance agrees on the counts: Material 3 navigation bar is for 3-5 destinations; Apple HIG tab bars also suggest keeping tabs few (about five on iPhone, more items go to a "More" tab). "Mobile only" is an oversimplification: iPadOS and tablets use tab bars and sidebars, and Material uses a navigation rail at medium widths. Use: compact width → bottom bar, medium → rail, expanded → persistent drawer / sidebar.
- The 40% / 56% figures are given without a source in the video and differ between voice ("40% fewer users click hidden menus") and screen (40% mobile, 56% desktop). They appear to come from hidden-navigation usability research (e.g. NN/g's 2016 hamburger study, which found hidden navigation lowered discoverability, more so on desktop). Treat them as directional, not as exact constants.
- Self-contradiction in the voice: the sidebar is "collapsible, but never hidden behind a click". Interpret as: users may collapse it, but default to expanded and keep icons (a rail) visible when collapsed.
- ARIA / semantics: wrap each navigation region in `<nav aria-label="Primary">` / `"Breadcrumb"`; mark the current destination with `aria-current="page"`. Breadcrumbs: ordered list inside `<nav aria-label="Breadcrumb">`, last item `aria-current="page"` (WAI-ARIA APG Breadcrumb pattern). Separators should be CSS or `aria-hidden`.
- Bottom tab bars for app destinations are navigation links, not the ARIA `tablist` pattern (that is for switching panels within a page).
- Hamburger button: `aria-expanded`, `aria-controls`, accessible name "Menu"; the drawer should trap focus while modal, close on Escape, and return focus to the button.
- Command palette: implement as a dialog containing a combobox with a listbox (APG Combobox pattern); `aria-activedescendant` for the highlighted result; support Ctrl K on non-Mac platforms; do not override browser / screen reader shortcuts.
- Tab bar items: icon plus visible text label, touch targets at least 44x44 pt (Apple) / 48x48 dp (Material); account for the bottom safe area (`env(safe-area-inset-bottom)`).
