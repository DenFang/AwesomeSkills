# Input masking: card number field done right

**Caption:** Card input is a special kind
**Hook:** Type 16 digits and watch them turn into a readable card number.

## Main rule
Format structured numbers as the user types (card numbers in groups of four, brand mark detected from the leading digit), keep the caret right after the character just typed when separators are inserted, stay neutral while typing and validate on blur, clean and reformat pasted values instead of rejecting them, and keep the stored value unformatted.

## Before / after
- **Raw run vs grouped.** "4242424242424242" (tagged "Hard to read") vs "4242 4242 4242 4242" (tagged "Readable"). Chunking a long digit string into groups of four matches how the number is printed on the card and lets the user compare and spot errors chunk by chunk instead of losing their place.
- **Brand detection.** A reference list (4 Visa, 5 Mastercard, 3 Amex) sits above an empty card field; typing "5" highlights Mastercard and immediately shows its mark inside the field. Instant recognition confirms the field understood the input and removes a separate "card type" selector.
- **Caret jumps vs caret held.** In "4242 4", when the mask inserts the space, the bad field throws the caret away from the last typed digit (shown far to the right, tagged "Caret jumps"); the good field keeps it right after the digit ("Caret held"). If the caret moves, the next keystroke lands in the wrong place and the user has to fix or retype; keeping it in place makes the mask invisible.
- **Premature vs patient validation.** While typing "4242 42", the bad field already shows a danger-styled border, warning icon and "Invalid card number" ("Premature"). The good field stays neutral during typing ("Patient") and after blur shows the full number with a success check and "Looks good". An error should mean "finished and wrong", not "not finished yet"; flagging mid-entry punishes normal progress.
- **Paste.** A value copied with dashes is pasted (tag "Pasted") and is converted to the field's own grouping, with the note "dashes removed, re-grouped". Rejecting a value that the system could normalise itself pushes cleanup work onto the user.
- **Show formatted, store raw.** "What the user sees" shows the grouped value; an arrow leads to "What you store", the digits without spaces. The mask is presentation; downstream code, comparisons and APIs need the canonical value.

## Do
- Insert separators automatically as the user types (groups of four for 16-digit cards).
- Detect the card network from the leading digits and show its mark inside the field as soon as it is known.
- Preserve caret position across reformatting, including edits in the middle of the value and deletions across a separator.
- Validate on blur; while typing, show no error state. After blur, show success or a specific error.
- On paste, strip spaces, dashes and other non-digits, then reformat.
- Keep the canonical value without formatting characters, separate from the displayed string.

## Don't
- Don't show a long number as one unbroken run.
- Don't move the caret to the end when a separator is inserted.
- Don't flag an error on the first keystroke or on an incomplete value while focus is still in the field.
- Don't reject pasted input because of separators.
- Don't store the formatting characters with the value.

## Voice-over summary
- Raw digits blur together; grouping by four as the user types turns 16 numbers into a readable card.
- The first digit names the brand (4 Visa, 5 Mastercard); show the logo as soon as it is known.
- Inserting a space must not make the caret jump; a smart field keeps it where the finger left it, because retyping is the worst outcome.
- Do not flag an error on the first keystroke: validate on blur, forgive while typing; the error colour should mean "done and wrong", not "unfinished".
- When someone pastes a number full of dashes, strip and reformat it; never reject a value you could clean yourself.
- Format what users see, store the raw digits: the mask is for humans, the value is for code.

## Notes for the skill
- Input attributes: `inputmode="numeric"`, `autocomplete="cc-number"`, `type="text"` (not `type="number"`, which strips leading zeros, adds spinners and breaks formatting). Use a visible `<label>`. Allow `maxlength` to accommodate separators (e.g. 19 for 16 digits plus 3 spaces, more for 19-digit cards).
- Caret math: compute the caret position as "number of digits before the caret" before reformatting, then map that digit index back into the formatted string. Handle Backspace when the caret is right after a separator (delete the preceding digit, not just the space).
- Grouping is network-dependent: "four by four" is an oversimplification. Amex has 15 digits grouped 4-6-5; some cards have 13-19 digits. Brand prefixes are also simplified: Mastercard includes 2221-2720 as well as 51-55; leading 3 also covers Diners Club and JCB (35), not only Amex (34/37). Use a maintained BIN/IIN table or the payment provider's element.
- Validation: on blur check length for the detected network and the Luhn checksum; show a specific message ("Card number is incomplete" vs "This number isn't valid") linked via `aria-describedby`, and set `aria-invalid="true"` only after validation fails. Once a field has shown an error, it is reasonable to re-validate on each keystroke so the error clears as soon as it is fixed (not covered by the video).
- "Store raw" applies to normalisation in general (phone, IBAN, postal codes), but for card numbers specifically you should not store the PAN yourself at all unless you are PCI DSS compliant; use the payment provider's hosted fields/tokenisation and store only the token and last four digits. The reel's JSON with a full card number is illustrative only.
- Screen readers: auto-inserted spaces can be announced oddly; keep the accessible value meaningful and avoid announcing every reformat. Give the brand mark a text alternative (e.g. visually hidden "Mastercard detected") or an `aria-live="polite"` announcement.
- Error and success must not rely on colour alone: use icon + text, and meet 4.5:1 for the message text.
- Masks that block characters should still accept paste and autofill; test browser autofill, which inserts the whole value at once.
