# Visual hierarchy: five levers that decide what users see first

**Caption:** not captured yet
**Hook:** Same layout and same content, but one version grabs attention instantly; five rules make the difference.

## Main rule
Create one clear focal point per view by stacking five levers: size (headline about 2x body), colour (neutral UI with a single accent reserved for what matters), contrast (bold vs light, filled vs outlined, bright vs muted), whitespace (extra padding around the most important element), and weight (at most three weights: 800 headings, 400 body, 300 captions).

## Before / after
- **No hierarchy vs clear hierarchy (overview).** Bad: dashboard where "revenue" and "users" labels, values and the small grey "view"/"manage" buttons all have similar size, weight and tone. Good: same content with a strong "Dashboard" title, large bold card titles, muted secondary lines and filled accent buttons ("View Report", "Manage"). Why: the eye needs a clear entry point and an ordering; equal emphasis forces it to scan everything.
- **Size.** Bad: "Monthly Revenue" title only slightly larger than the description. Good: title scaled to about twice the body size (badge "2x"). Why: the largest element is fixated first; a 20% difference is too small to read as a different level.
- **Colour.** Bad: every nav item and metric gets its own colour (outlined nav pills each in a different hue, three metrics each in a different colour). Good: nav and metrics turn neutral; only the active nav item ("Pricing") and the one key metric ("Growth +24%") use the accent ("One accent color. Only where it matters."). Why: colour attracts attention only when it is scarce; many colours cancel each other out.
- **Contrast.** Good pairs: Bold 800 heading vs Light 300 text; filled primary "Get Started" vs outlined/ghost "Learn More"; bright text vs muted text ("Bigger difference = stronger signal"). Why: the larger the difference between two elements, the faster their roles are distinguished.
- **Whitespace.** Bad: "Start Free Trial" squeezed into the same tight list rhythm as Features, Pricing, Documentation. Good: the trial block gets a larger box and generous padding (48px marker) while secondary items stay compact ("Not empty. Intentional."). Why: isolation signals importance and separates the primary action from the list.
- **Weight.** Good: "Monthly Revenue Report" at 800 (Heading), description at 400 (Body), "Last updated 3 hours ago" at 300 (Caption); a second card demonstrates reading order 1-2-3 ("You read this first", "Then this paragraph gives you context", small details last). Why: weight alone establishes reading order even at similar sizes.

## Do
- Make the primary heading about 2x the body size.
- Keep the UI neutral and reserve one accent colour for primary actions, links, active states and key numbers.
- Pair contrasting treatments: bold vs light, filled vs outlined, strong vs muted text.
- Give the single most important element noticeably more padding than its neighbours (the video: double).
- Limit type to three weights (800 / 400 / 300 in the video).
- Combine levers; no single lever carries the hierarchy alone.

## Don't
- Don't make headings only marginally (about 20%) larger than body.
- Don't colour every element differently.
- Don't give every element equal emphasis or equal spacing.
- Don't rely on size alone.

## Voice-over summary
- Same layout and content, but one grabs attention; five rules are enough.
- Size: the eye goes to the biggest element first; make the headline twice the body size, not 20% bigger.
- Colour: one accent used only where people should look (buttons, links, key numbers); everything else neutral.
- Contrast: light text on dark cards, bold headings next to light body; bigger difference, clearer hierarchy.
- Whitespace: double the padding around important elements; "white space doesn't mean empty, it means intentional".
- Weight: three weights maximum (800 headings, 400 body, 300 captions); weight alone creates a reading order.

## Notes for the skill
- Tokens: define a type scale (e.g. caption, body, heading, display) where heading ≈ 2x body for the primary title; a modular ratio (1.25-1.333 per step) reaches about 2x within 2-3 steps. Define `--accent` once and use it only for primary/active/key elements.
- Accent colour must not be the only state indicator: the active nav item also needs a non-colour cue (filled shape, underline, `aria-current="page"`), and key numbers need labels (WCAG 1.4.1).
- Contrast lever vs accessibility: "muted" text must still meet 4.5:1 for normal text (3:1 for large text, WCAG 1.4.3). The muted text sample in the reel's contrast demo looks well below that on its dark card; use it only for decorative/disabled text, never for content the user must read.
- Weight 300 at caption sizes (≤12-13px) on dark backgrounds is often hard to read, especially on low-DPI screens; consider 400 for captions and get the hierarchy from size and colour instead. Verify the chosen font actually ships 300/400/800 (or a variable axis), otherwise the browser synthesises bold.
- Whitespace: build spacing on a scale (e.g. 4/8-px based) and express "important element" padding as one or two steps up, rather than ad-hoc values; 48px is the demo value.
- Heading levels for structure (`h1`-`h3`) should follow the visual hierarchy so screen-reader users get the same order.
