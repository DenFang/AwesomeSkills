# Five common CSS mistakes and their modern fixes

**Caption:** Lists five mistakes seen in most codebases: `height: 100%` without a parent height, `margin-bottom` on every element, a media query for every breakpoint, `z-index: 9999` escalation, centring with absolute positioning; the fixes are on the slides; bonus tip: cascade layers for specificity control.
**Hook:** The cover claims your CSS is broken and promises 5 mistakes you are probably making.

## Main rule
Replace fragile CSS habits with primitives that state intent: a viewport-relative minimum height instead of an unresolvable percentage, parent `gap` instead of child margins, one fluid `clamp()` value instead of stepped breakpoint overrides, a fresh stacking context instead of ever larger z-index, grid alignment instead of absolute offsets, and `@layer` order instead of specificity or `!important` fights.

## Before / after
Each mistake slide shows a DON'T panel (danger top edge) and a DO panel (success top edge).
- **height: 100% trap (slide 2).** Bad: `.container { height: 100%; }` while the parent has no height, so the percentage resolves to auto and does nothing. Good: `.container { min-height: 100dvh; }`. Why: a percentage height needs a definite containing-block height all the way up the chain; a viewport unit does not depend on ancestors, and `min-height` lets content grow past it instead of overflowing. `dvh` tracks the dynamic mobile viewport as browser toolbars show and hide.
- **Margins everywhere (slide 3).** Bad: `.card { margin-bottom: 24px; }` patched with `.card:last-child { margin-bottom: 0; }`. Good: `.grid { display: flex; flex-direction: column; gap: 24px; }`. Why: spacing becomes a property of the container, applied only between items, so there is no trailing gap to cancel, no collapsing margins, and children stay reusable in other contexts.
- **Stepped breakpoints (slide 4, titled Fixed Widths Break).** Bad: `h1 { font-size: 48px; }` overridden to 32px under 768px and 24px under 480px. Good: `h1 { font-size: clamp(1.5rem, 4vw, 3rem); }`, one line for all screens. Why: size scales continuously between a minimum (24px at a 16px root) and a maximum (48px), so there are no jumps at arbitrary widths and no rules to keep in sync. The bounds equal the old 24px and 48px.
- **z-index: 9999 (slide 5).** Bad: `.modal { z-index: 9999; }` then `.tooltip { z-index: 99999; }`, an escalation war. Good: `.modal { isolation: isolate; z-index: 1; }`, a new stacking context as a clean slate. Why (slide subtitle: the number is not the real problem): z-index values compete only within the same stacking context, so the fix is controlling where contexts are created; inside an isolated context small local values are enough.
- **Absolute centring (slide 6).** Bad: `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%)`. Good: `.center { display: grid; place-items: center; }`, or even simpler `.parent { align-content: center; }`. Why: alignment stays in normal flow, the box can grow without overflowing its offsets, and there is no transform that can land on half pixels.
- **Bonus, @layer (slide 7).** Declare `@layer base, components, utilities;`, put `a { color: ...; }` in `base` and a `.text-*` colour utility in `utilities`; the utility always beats base. Why: between layers, declared order decides the winner before selector specificity is compared, so there is no need for `!important`.

## Do
- Use `min-height: 100dvh` (with a `100vh` fallback line before it) for full-screen shells; use flex or grid stretching for children that should fill a parent.
- Own spacing in the parent with `gap` (flex and grid).
- Use `clamp(min-rem, preferred, max-rem)` for type and spacing that should scale; keep media queries for real layout changes.
- Create stacking contexts deliberately (`isolation: isolate` on component roots) and keep z-index values small and tokenised.
- Centre with grid or flex alignment; use `align-content: center` on a block parent where supported.
- Declare the layer order once at the top of the stylesheet.

## Don't
- Don't use `height: 100%` unless every ancestor has a definite height.
- Don't add bottom margins to every component and then cancel the last one.
- Don't write three breakpoint overrides for one font size.
- Don't escalate z-index numbers; a larger number cannot escape its parent stacking context.
- Don't centre in-flow content with absolute positioning plus a translate.
- Don't use `!important` to win specificity fights that layer order can settle.

## Notes for the skill
- height: `min-height: 100dvh` is not a general replacement for `height: 100%`: it sizes to the viewport, so it fits page shells and full-screen sections, not a child that should fill a card or panel (use `flex: 1`, `align-self: stretch` or grid `1fr` there). Prefer `min-height` over `height` so content can grow; check current support for `dvh` and keep a `vh` fallback.
- gap: switching a stack to flex column also changes child behaviour (children become flex items: no margin collapse, `min-width: auto`, stretch by default). For prose flow content, a `.stack > * + *` margin rule is still a valid alternative.
- clamp: a preferred value of pure `4vw` does not respond to browser text zoom between the bounds, which can conflict with WCAG 1.4.4 Resize Text; combine it with a rem term, for example `clamp(1.5rem, 1rem + 2.5vw, 3rem)`. With the slide's values the size sits at the 1.5rem minimum below about 600px wide and reaches the 3rem maximum at about 1200px (at a 16px root).
- z-index: the slide's fix is incomplete. `z-index` creates a stacking context only on a positioned element (or a flex or grid item), and `isolation: isolate` on the modal isolates its children, not the modal itself; the modal's own `z-index: 1` still competes in the parent context. The robust pattern is `isolation: isolate` on component or app roots so internal z-index cannot leak, a small token scale for the remaining global layers, and the native top layer (`<dialog>` with `showModal()`, the `popover` attribute) for modals and tooltips, which renders above any z-index.
- Centring: `align-content: center` on a block container centres vertically only (block axis), not horizontally; check current support. Absolute centring is still correct for overlays that must leave the flow (a spinner over a card); the mistake is using it for normal layout.
- @layer: unlayered styles beat all layered styles, and for `!important` declarations the layer order is reversed. Third-party CSS can be placed in a low layer with `@import url(lib.css) layer(vendor);`. Check current support for older targets.
- Accessibility: grid and flex reordering (`order`, `grid-area`) can desynchronise visual and DOM order (WCAG 1.3.2, 2.4.3); keep source order meaningful.
