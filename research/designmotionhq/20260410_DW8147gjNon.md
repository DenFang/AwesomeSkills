# Five common CSS mistakes and their modern fixes

**Caption:** Lists five mistakes seen in most codebases: `height: 100%` without a parent height, `margin-bottom` on every element, a media query for every breakpoint, `z-index: 9999` escalation, centring with absolute positioning; the fixes are on the slides; bonus tip: cascade layers for specificity control.
**Hook:** The cover claims your CSS is broken and promises 5 mistakes you are probably making.

## Main rule
Replace fragile CSS habits with layout primitives that express intent: definite heights or flex/grid stretching instead of orphan percentages, container `gap` instead of per-element margins, fluid and intrinsic layouts instead of many breakpoints, a token scale and stacking contexts instead of ever larger z-index, grid/flex centring instead of absolute offsets, and `@layer` to control the cascade instead of specificity hacks.

## Before / after
Bad versions are from the caption; good versions are the standard fixes (assumed to match the slides, not verified).
- **Percentage height.** Bad: `height: 100%` on a child whose parent has auto height, so it resolves to auto and nothing fills. Good: give the chain a definite height, use `min-height: 100dvh` on the page shell, or let flex/grid stretch the child (`flex: 1`, grid rows `1fr`). Why: percentage heights only resolve against a definite containing-block height.
- **Margin on every element.** Bad: `margin-bottom` on each item, leaving a trailing gap after the last one and colliding with margin collapse. Good: `display: flex; flex-direction: column; gap: ...` or grid `gap` on the parent. Why: spacing becomes a property of the container, consistent and with no edge cases.
- **A media query per breakpoint.** Bad: many viewport breakpoints tweaking sizes. Good: fluid values with `clamp()`, intrinsic grids such as `repeat(auto-fit, minmax(16rem, 1fr))`, and container queries for components. Why: layouts adapt continuously and to their container, with far fewer rules.
- **z-index 9999 wars.** Bad: ever larger numbers. Good: a small z-index token scale (base, dropdown, sticky, overlay, modal, toast) and `isolation: isolate` to create local stacking contexts; native top layer for `<dialog>` and popovers. Why: z-index only competes within a stacking context, so big numbers often do not even work.
- **Absolute centring.** Bad: `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%)`. Good: `display: grid; place-items: center` (or flex with centring). Why: no removal from flow, no blurry sub-pixel transforms, content can grow.
- **Bonus.** Specificity fights fixed with `@layer reset, base, components, utilities;` so later layers win regardless of selector weight.

## Do
- Use `gap` for spacing between siblings in flex and grid.
- Define a z-index scale as tokens and document what each level is for.
- Prefer `clamp()`, intrinsic grids and container queries; keep viewport breakpoints for real layout shifts.
- Centre with grid or flex.
- Order the cascade with `@layer` (reset, base, components, utilities).

## Don't
- Don't use `height: 100%` without a definite parent height.
- Don't put bottom margins on every component.
- Don't escalate z-index numbers to win a stacking fight.
- Don't centre in-flow content with absolute positioning and transforms.
- Don't use `!important` or extra selectors to beat specificity when layers would solve it.

## Notes for the skill
- The fixes are not visible in the available material; everything under Before/after Good, Do and Don't is standard CSS practice reconstructed from the caption's mistakes. Verify against the original slides if they become available.
- `dvh`, `@layer`, container queries and `place-items` are newer features: check current support for the target browsers.
- `@layer` subtlety: unlayered styles beat all layered styles, and for `!important` the layer order is reversed. Third-party CSS can be imported into a low layer (`@import url(lib.css) layer(vendor);`).
- Margin collapse is not always a bug; the real issue is spacing owned by children. The owl selector (`.stack > * + *`) is an older alternative to `gap` for flow content.
- Absolute centring is still correct for overlays that must leave the flow (e.g. a spinner over a card); the mistake is using it for normal layout.
- z-index scale should also cover the native top layer: `<dialog>` with `showModal()` and `popover` render above any z-index, which removes most of the reasons for huge values.
- Accessibility: grid/flex reordering (`order`, `grid-area`) can desynchronise visual and DOM order (WCAG 1.3.2, 2.4.3); keep source order meaningful.
