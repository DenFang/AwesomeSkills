# Golden ratio for spacing, layout and type

**Caption:** The golden ratio applied to design
**Hook:** Two versions of the same layout, one cheap and one expensive; the claimed difference is the number 1.618.

## Main rule
Derive spacing and type sizes from one base value and one constant ratio (the video uses 1.618: spacing 8, 13, 21, 34, 55 px; type 16, 26, 42, 68 px) and split two-panel layouts about 62/38 with primary content on the larger side, instead of choosing gaps and sizes ad hoc.

## Before / after
1. **Whole screen (0:00-0:02).** Bad: a card layout with tight, uneven gaps, a muted full-width bottom button and elements crowding the top. Good: the same content with larger, graduated spacing (more air above the title and between groups) and the bottom CTA in the accent colour; a golden spiral overlays the good version. Why: consistent, related spacing makes grouping legible (gestalt proximity), so the layout reads as intentional.
2. **Spacing values (0:20-0:23).** Bad ("Random"): gaps of 12, 7, 20, 5, 15 px with no relation between them. Good ("Golden"): 8, 13, 21, 13, 8 px, all from one scale. Why: a limited set of related steps produces a repeatable rhythm; arbitrary values create visual noise and inconsistent grouping.
3. **Layout split (0:24-0:33).** An empty frame is divided by a vertical line into 61.8% "Content" (title, two stat cards, tabs, text) and 38.2% "Actions" (nav list Dashboard, Analytics, Settings, Profile, plus an accent "Upgrade" button at the bottom). Why: an unequal split creates a clear primary and secondary area, unlike a 50/50 split where both compete.
4. **Type scale (0:34-0:46).** Four levels stack up: 16 body, 26 subheading, 42 heading, 68 display, each labelled "x1.618". Why: a constant ratio gives distinct, predictable steps of hierarchy.

## Do
- Pick one base unit and one ratio; derive spacing tokens from them and round to whole pixels.
- Use the larger panel of an unequal split for primary content and the smaller one for navigation or secondary actions.
- Derive heading sizes from the body size with the same ratio, so the hierarchy has clear steps.
- Use only scale values for gaps, never one-off numbers.

## Don't
- Don't pick padding and font sizes by eye per component.
- Don't apply the ratio so rigidly that it fights real content or an existing 4/8 px grid (the page itself warns about this).

## Notes for the skill
- The useful, testable rule is "use a modular scale and a limited token set". The ratio itself is a choice: 1.618 gives very large jumps (68 px display after only three steps), which is often too steep for dense product UI; 1.2-1.333 type ratios are more common in app interfaces, 1.5-1.618 suit marketing pages with few levels.
- Claims that need correcting: "your brain is literally wired to find it beautiful" is not supported by perception research (preference studies for phi rectangles are inconsistent); the nature/Mona Lisa examples are popular myth. The statement that Stripe, Linear and Airbnb "all use this exact scale" is unverified and should not be repeated as fact. Apple pages are credited without evidence.
- Spacing values 13 and 21 do not sit on a 4 px or 8 px grid. If the project has an 8 px grid, keep it (e.g. 4, 8, 12, 16, 24, 32, 48, 64) rather than mixing in phi values; consistency of the scale matters more than which ratio it uses.
- Implementation: expose tokens as CSS custom properties (`--space-1: 8px; --space-2: 13px; ...`, `--text-body: 1rem; --text-h3: 1.625rem; --text-h2: 2.625rem; --text-display: 4.25rem`). Use `rem` for type so user font-size settings scale it (WCAG 1.4.4 Resize Text). On small screens reduce the display step, e.g. with `clamp()`, so 68 px headlines do not overflow.
- Layout split: `grid-template-columns: 1.618fr 1fr` gives the 61.8/38.2 split; collapse to a single column on narrow viewports, with the primary content first in DOM order.
